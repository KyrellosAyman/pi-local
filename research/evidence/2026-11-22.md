# Pi Local follow-up results, 22 November 2026

The [0.1.3 report](../pi-local-v0.1.3.pdf) adds these results to the [0.1.2 evidence record](2026-11-21.md). Live observations used the original 64,000-token optimized model profile with an exclusive slot. Scripted desktop tests used the same pinned Pi RPC with a separate local fixture provider.

| Trial | Result | Limits |
| --- | --- | --- |
| Clarification, fully specified request | No questions and an exact requested response. | One live prompt. |
| Clarification, custom answer | One question and a typed fourth-row answer. Pi used the supplied audience in the response. | Acceptance tests targeted the interaction. |
| Clarification, one-click recommendation | One click submitted the first choice. Pi stored the selection once and used it without asking again. | An earlier live version saved the choice but repeated the question. The fix supplies the saved answer as user input while preserving the original transcript. |
| Clarification recovery | The scripted desktop recovered the unanswered card, then a committed answer before RPC acknowledgment. It retained one original user message and one brief. | Scripted provider. |
| First plan review | The final live run committed one corrected plan from one review call and completed all three steps. Independent grading matched the two 76-byte files and verified the original was unchanged. | One 333-second task. Two earlier runs exposed a status-format retry and a valid-looking receipt that listed gaps while keeping the draft unchanged. |
| First plan review recovery | The scripted desktop preserved a pending review and recovered a committed review without repeating it. It refused an unchanged draft with unresolved findings. | Scripted provider. |
| Stock near-64k workflow | Two requests used 57,884 and 57,902 input tokens, each with a one-token reply budget. No work tool ran. | One fixed long-source task. |
| Reply budget alone | The model reached tools, then a later request overflowed at 77,891 input tokens. | Full tool schemas were still present. |
| Reduced tool schemas, later format correction | The live replay made one registered read, closed its plan, and returned all three exact codes on the requested line. All seven provider requests matched the native log. The run took 944.57 seconds, reached 61,232 input tokens and did not compact. | Local text workload only. Six near-limit requests had a median of 19.566 tokens/s. Three were below 20, none reached 40, and none of 263 samples reached joint 95% CPU and RAM. |

The [reproduction guide](../../docs/reproducibility.md#offline-fixture-checks) lists the runnable fixtures. The live prompts for clarification used benign fictional audiences. No private model profiles, sessions, or logs are required by the fixture suite.
