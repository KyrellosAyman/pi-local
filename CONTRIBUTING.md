# Contributing to Pi Local

Pi Local is a Windows desktop harness for local models and reproducible agent research. See the [setup and reproduction guide](docs/reproducibility.md) for the supported environment and local fixtures.

## Report a bug or propose a change

For a bug, include the Pi release or commit, Windows and runtime versions, and a small example that reproduces it. For an experiment, record the model, hardware, context size, prompt or public fixture, grading criteria, and full task outcome. Include failures and skipped checks. For a larger change, open an issue first to agree on its scope.

Keep credentials, private conversations, user data, and raw local logs out of issues and patches. Use the [security policy](SECURITY.md) for suspected vulnerabilities.

## Send a pull request

Fork the repository, create a topic branch, and open a pull request against `main`. Explain what changed, how you verified it, and any limitations. Run the relevant checks in the reproduction guide. For a research change, update the evidence and follow the [release record instructions](docs/releasing.md).

@KyrellosAyman is the repository owner and code owner. The owner reviews and approves the current revision of contributions and makes the merge decision. Changes after approval need another review. Automated reviews and test results are evidence for the owner’s decision. A contributor works from a fork. Write access to this repository is reserved for the owner.

## Rights and attribution

Submit work you have the right to share under [Apache License 2.0](LICENSE). When material comes from another project, identify its source, applicable license, and required notices. Keep existing notices with the affected files. Describe the provenance of any public data or benchmark inputs.
